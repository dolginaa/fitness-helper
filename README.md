# Fitness Helper — Telegram-бот трекинга тренировок

Бот на **Go 1.25+** с чистой архитектурой: `domain` ← `usecase` ← адаптеры. У одних и тех же сценариев два интерфейса — **чат с ботом** и **Mini App** (веб‑страница внутри Telegram), а до Telegram бот добирается одним из двух транспортов — **Bot API** или **MTProto**, в том числе через прокси.

## Требования

- Go 1.25+
- Docker и Docker Compose (для PostgreSQL и миграций)
- [sqlc](https://docs.sqlc.dev/en/latest/overview/install.html) — только если меняете SQL-запросы (`make sqlc`)

## Быстрый старт (локально)

1. Скопируйте окружение и задайте токен бота от [@BotFather](https://t.me/BotFather). Файл `.env` подхватывается при старте (`godotenv`).

   ```bash
   cp .env.example .env
   # Отредактируйте .env: BOT_TOKEN, при необходимости DATABASE_URL
   ```

2. Поднимите Postgres и примените миграции:

   ```bash
   make docker-up
   make migrate-up
   ```

3. Запустите бота на хосте (БД на `localhost:5432`):

   ```bash
   make run
   ```

### Как пользоваться

Всё управление — кнопками; команды нужны только как быстрый вход (они есть в меню бота рядом с полем ввода).

1. **Новая тренировка** → группа мышц → упражнение. В списке упражнений видно, что и когда делали в прошлый раз, а сделанные сегодня отмечены ✅.
2. **Подход — одним сообщением:** `10 50` (10 повторов по 50 кг). Понимает `10x50`, `10×52,5`, `10 50 кг`; несколько подходов сразу — `10 50, 8 55` или с новой строки. Без веса — `12 0`. По-старому тоже можно: сначала повторы, потом вес.
3. Под упражнением кнопки: **«Ещё 10×50»** — повторить подход одним нажатием (первый подход подставляется из прошлой тренировки), **«Убрать последний»** — исправить опечатку.
4. Нет упражнения в списке — **«Своё упражнение»**, название вводится текстом.
5. **«Завершить»** показывает итог (упражнения, подходы, тоннаж) и просит подтверждение. Пустая тренировка не сохраняется.

**Вес, свой вес, резинка.** Подтягивания можно делать на гравитроне с весом, с резинкой или с собственным весом, отжимания — только с собственным. Поэтому у каждого упражнения есть виды нагрузки, а у каждого подхода свой вид:

| Вид | Как записать | Пример | В списках |
|---|---|---|---|
| Вес | повторы и вес | `10 50` | `10×50` |
| Свой вес | повторы (и доп. вес, если есть) | `15` или `8 5` | `15×св.вес`, `8×св.вес+5` |
| Резинка | повторы и уровень резинки 1–10 | `12 4` | `12×рез.4` |

Если у упражнения несколько видов, над кнопками подхода появляется переключатель. Бот сам начинает с вида, в котором вы делали упражнение в прошлый раз. Кнопка **«⚙️ Нагрузка»** (в Mini App — «Нагрузка упражнения») отмечает, с чем упражнение делается. Это общая настройка упражнения. Тоннаж считается только по весу: у резинки и своего веса его нет, для них считаются повторы.

**Итог тренировки** после «Завершить» содержит длительность, повторы и тоннаж с сравнением с прошлой тренировкой, рекорды (вес, объём упражнения, повторы), что изменилось против прошлого раза, упражнения, сделанные впервые, число тренировок за 7 дней и сколько дней прошло с прошлой.

Тренировку нельзя потерять: если начать новую при незавершённой, бот спросит, продолжить или завершить; «Продолжить тренировку» в меню возвращает на тот же экран.

| Команда | Описание |
|---------|----------|
| `/start` | Главное меню |
| `/startnew` | Новая тренировка |
| `/history` | История: список с датами и группами мышц, листается кнопками |
| `/workout ДД.ММ.ГГГГ` | Тренировки за день (`/workout 15.03` — в текущем году) |
| `/progress` (`/last`) | Последние результаты по группе мышц и графики |
| `/backup` | Выгрузка, импорт, еженедельный бекап |
| `/export`, `/backup_on`, `/backup_off` | То же, что кнопки в разделе «Бекап» |

Импорт: пришлите боту `.zip` из выгрузки и выберите «Добавить к данным» или «Заменить всё» (замена спрашивает подтверждение).

Графики (нужно ≥2 тренировок с упражнением в одном виде нагрузки):

- **По упражнению** — приходит при выборе упражнения в тренировке и в разделе «Прогресс»: линия макс. веса и под ней столбики объёма за тренировку (вес × повторы), чтобы был виден прогресс и по весу, и по повторам. Для своего веса линия — повторы в подходе, для резинки — уровень резинки, столбики — всего повторов. Веса, повторы и резинки не рисуются на одной оси, поэтому график строится по одному виду нагрузки: по последнему, где достаточно тренировок.
- **По группе мышц** — сетка маленьких графиков, по одному на упражнение: текущий макс. вес, изменение за период и линия. У каждого упражнения своя шкала, ось времени общая.
- «Все графики» в разделе «Прогресс» присылает графики всех упражнений группы альбомом.

Посмотреть графики на своих данных без бота: `CHART_EXPORT=$PWD/export.json CHART_OUT_DIR=$PWD/bin/charts go test ./internal/charts -run Preview`.

## Подключение к Telegram и прокси

Транспорт выбирается переменной `TELEGRAM_TRANSPORT`; для пользователя в чате разницы нет.

| | `botapi` (по умолчанию) | `mtproto` |
|---|---|---|
| Протокол | HTTPS, Bot API | MTProto — как у приложений Telegram |
| Что нужно | только `BOT_TOKEN` | ещё `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` приложения с [my.telegram.org/apps](https://my.telegram.org/apps) |
| Прокси (`TELEGRAM_PROXY`) | `socks5://user:pass@host:1080` или `http://user:pass@host:3128` | ссылка MTProto‑прокси: `https://t.me/proxy?server=…&port=…&secret=…` |

- **MTProto‑прокси работает только с `mtproto`**: Bot API ходит по HTTPS, а такой прокси пропускает лишь протокол MTProto. Если указать ссылку `t.me/proxy` при `botapi`, бот не запустится и объяснит это.
- Для `botapi` без `TELEGRAM_PROXY` используется `HTTPS_PROXY` из окружения, если он задан.
- При `mtproto` бот один раз входит по токену и сохраняет сессию в `TELEGRAM_SESSION_FILE` (по умолчанию `data/telegram-session.json`, в Docker — том `/data`). Файл — секрет: с ним можно действовать от имени бота.
- При `mtproto` сообщения, отправленные, пока бот был выключен, после запуска могут не дойти: бот не хранит позицию в потоке обновлений между перезапусками (Bot API хранит недоставленное до суток).

```bash
# .env — MTProto через тот же прокси, что и в приложении Telegram
TELEGRAM_TRANSPORT=mtproto
TELEGRAM_API_ID=1234567
TELEGRAM_API_HASH=0123456789abcdef0123456789abcdef
TELEGRAM_PROXY=https://t.me/proxy?server=HOST&port=443&secret=SECRET
```

Нет связи (`TLS handshake timeout`, `connection refused`) — почти всегда сеть: проверьте прокси и что его вид соответствует транспорту. Токен бота в логах маскируется; при утечке перевыпустите его в BotFather (`/revoke`).

## Mini App

Mini App — веб‑интерфейс внутри Telegram: те же тренировка, история и прогресс, но экранами с кнопками и полями вместо переписки. Подход записывается степперами «повторы / вес», уже заполненными наиболее вероятными значениями.

Состояние общее с чатом: тренировку можно начать в приложении и продолжить в чате, и наоборот.

Включение:

```bash
WEBAPP_ADDR=:8080                    # где слушать
WEBAPP_URL=https://fit.example.com/  # публичный HTTPS-адрес этого же сервера
```

Telegram открывает Mini App только по HTTPS, поэтому перед портом нужен обратный прокси с сертификатом (Caddy, nginx) или туннель (например `cloudflared tunnel --url http://localhost:8080`). Когда `WEBAPP_URL` задан, бот показывает кнопку «📱 Открыть приложение» в главном меню и кнопку меню чата.

- Страница грузится с вашего сервера напрямую, не через Telegram и не через `TELEGRAM_PROXY`.
- Кто делает запрос, сервер узнаёт по подписи Telegram в данных запуска (проверяется токеном бота); чужие данные не отдаются.
- Локально, без Telegram: `WEBAPP_ADDR=127.0.0.1:8080 WEBAPP_DEV_USER_ID=<ваш Telegram id>` и откройте `http://127.0.0.1:8080/` в браузере. Эта переменная отключает проверку подписи — вместе с `WEBAPP_URL` бот с ней не запустится.
- Посмотреть страницу на данных из выгрузки, без базы и бота: `WEBAPP_PREVIEW=127.0.0.1:8099 CHART_EXPORT=$PWD/export.json go test ./internal/webapp -run Preview -timeout 0`.

## Порядок в списке упражнений

Упражнения, которые отличаются только написанием («подтягивания» и «Подтягивания»), могли появиться, например, из старого стартового списка и импорта. Новые такие дубли не создаются: имена сравниваются без учёта регистра, пробелов, знаков и е/ё, в том числе при импорте. Уже накопившиеся убирает команда, которая **ничего не меняет, пока вы не добавите `-apply`**:

```bash
make exercises-report          # что неаккуратно: дубли, похожие названия, упражнения без тренировок
make exercises-dedupe          # показать, что будет объединено
make exercises-dedupe APPLY=1  # объединить
```

- Сначала сделайте выгрузку в боте (`/export`).
- Дубли объединяются так: остаётся написание с заглавной буквы, а записи тренировок переходят к нему. Если в одной тренировке были оба написания, их подходы складываются в одну запись. Каждое объединение выполняется в одной транзакции и откатывается, если число подходов изменится.
- Похожие, но разные названия («Сгибание ног сидя» и «Сгибания ног сидя») автоматически не объединяются: решить, одно ли это упражнение, можете только вы. Объединить вручную: `go run ./cmd/exercises merge -from ID -to ID -apply`, удалить упражнение без тренировок: `go run ./cmd/exercises delete -id ID -apply`. id показывает `report`.
- Бот лучше остановить на время объединения: упражнение, которое сейчас вводится, исчезнет из-под него.

## Запуск в Docker Compose (бот + БД)

После первого `make migrate-up` (схема и seed в БД):

```bash
cp .env.example .env
# Укажите BOT_TOKEN в .env
docker compose up -d --build bot
```

Сервис `bot` подключается к `postgres` по внутреннему URL; `DATABASE_URL` в compose переопределён для контейнера.

## Продакшен на VPS

1. Установите Docker (или Go + systemd).
2. Склонируйте репозиторий, создайте `.env` с `BOT_TOKEN` и при необходимости `DATABASE_URL`.
3. Выполните миграции, затем поднимите сервисы: `docker compose up -d --build bot`.
4. Альтернатива без Docker для бота: соберите `make build`, перенесите `bin/bot` на сервер, задайте переменные окружения и запустите unit в systemd с `Restart=always`.

Все переменные с пояснениями — в [.env.example](.env.example). Обязательны `BOT_TOKEN` и `DATABASE_URL`; `TZ` — часовой пояс для дат в сообщениях и для `/workout` (в Docker Compose по умолчанию `Europe/Moscow`, при локальном запуске — пояс системы).

## Разработка SQL

После правок в `sql/queries/*.sql` или `sql/schema.sql` выполните `make sqlc`. Миграции в `migrations/` должны соответствовать схеме для sqlc (`sql/schema.sql`).

## Структура

Зависимости направлены внутрь: `domain` не знает ни о ком, `usecase` знает только `domain`, всё остальное — адаптеры, которые собираются в `cmd/bot`.

- `internal/domain` — сущности, состояние диалога, ошибки и порты репозиториев.
- `internal/usecase` — сценарии: тренировка (разбор ввода подходов по видам нагрузки, повтор, отмена), история и прогресс, итог тренировки (рекорды, сравнение), чистка упражнений, бекап. Возвращает данные, а не тексты.
- `internal/repository/postgres` — реализация портов; `internal/repository/sqlcgen` — код sqlc; `internal/repository/memory` — реализация в памяти для тестов.
- `internal/chat` — разговор с пользователем без привязки к транспорту: сообщение, нажатие кнопки, клавиатура и интерфейс `Messenger`.
- `internal/handlers` — диалог в чате: маршрутизация сообщений и кнопок, экраны, еженедельный бекап. Работает через `chat.Messenger` и не знает, как сообщения попадают в Telegram.
- `internal/telegram/botapi`, `internal/telegram/mtproto` — два транспорта, реализующие `chat.Messenger`; `internal/telegramhttp` — HTTP‑клиент Bot API (таймауты, прокси, маскировка токена).
- `internal/webapp` — Mini App: JSON API с проверкой подписи Telegram и встроенная в бинарник страница (`static/`).
- `internal/view` — тексты сообщений; `internal/keyboards` — кнопки.
- `internal/charts` — PNG-графики прогресса по виду нагрузки; используются и чатом, и Mini App.
- `cmd/exercises` — чистка списка упражнений (дубли, ручное объединение).
- `cmd/bot` — точка входа: конфиг (Viper), пул БД, выбор транспорта, запуск чата и Mini App, graceful shutdown.
- `migrations` — схема и seed упражнений.
- `pkg/logger` — JSON slog.

## Тесты

```bash
make test
```

- `usecase`, `handlers` и `webapp` тестируются на репозиториях в памяти: диалог в чате прогоняется целиком через фейковый `Messenger`, API Mini App — через настоящие HTTP‑запросы с подписью.
- Транспорт Bot API проверяется на фейковом сервере Bot API (формат запросов, кнопки Mini App, альбомы, отсутствие токена в ошибках). MTProto‑транспорт тестами покрыт только в части разбора прокси‑ссылок и кнопок: для остального нужен настоящий Telegram.
- `make test-integration` проверяет SQL на настоящем Postgres. Тест создаёт временную схему, применяет в неё миграции и удаляет её — данные в базе не трогает. Без `TEST_DATABASE_URL` пропускается.
- Посмотреть на графики из тестов: `CHART_OUT_DIR=/tmp go test ./internal/charts`.
